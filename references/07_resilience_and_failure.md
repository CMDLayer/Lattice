# Reference Primer — Resilience and Failure

## Core idea

A cross-dimensional architecture can create leverage and also create cascading fragility. Resilience must be designed.

## Load-bearing bridge
Failure materially damages the meta objective.

Ask:
- Can it be strengthened?
- Can it be observed early?
- Can it be replaced?
- Can we reduce dependency on it?

## Graceful degradation
A good architecture may lose some benefit while preserving core viability.

## Redundancy
Redundancy is useful when failure cost is high, but excessive redundancy wastes resources.

## Diversity of causal paths
Two independent routes to the same useful condition may be stronger than duplicate copies of the same route.

## Leading indicators
Monitor states before final outcomes.

Example:
Do not wait for "partnership failed." Track:
- response time,
- qualified introductions,
- acceptance rate,
- operational effort.

## Agent questions

- What is the weakest link?
- What failure could cascade?
- What signal appears first?
- What survives if this bridge disappears?
- Can a different dimension create a substitute state?
