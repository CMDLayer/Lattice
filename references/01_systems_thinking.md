# Reference Primer — Systems Thinking

## What CDCO borrows

CDCO borrows the idea that local actions participate in wider systems and can create delayed, indirect, and unintended effects.

## Key concepts

### System boundary
A boundary defines what the current model includes. CDCO intentionally uses multiple boundaries: each dimension has a local boundary, while the orchestration has a broader boundary.

### Feedback
An effect can return to influence the source dimension.

Example:
`operations measurement -> better sales qualification -> cleaner demand -> lower delivery variability -> better operations`

### Delay
Cause and effect may be separated in time. A bridge can be real yet unusable if its effect arrives too late.

### Leverage point
A relatively small intervention that materially changes system behavior.

CDCO translation:
A high-leverage bridge produces a state change with disproportionate downstream usefulness.

### Local optimization
Improving one subsystem can worsen the whole.

CDCO implication:
Local plans should be coherent, but the agent must inspect system-level externalities and tradeoffs.

### Emergence
The overall pattern may not be obvious from any one component.

CDCO implication:
The orchestration may create value that cannot be seen by inspecting a single plan.

## Questions for the agent

- What boundary am I using?
- What effects occur outside the local boundary?
- What delays matter?
- What feedback loops appear?
- Is a local improvement creating a system-level cost?
- Where is there leverage?
